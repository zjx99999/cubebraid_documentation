部署与运行时依赖
================

CubeBraid SDK 的 Windows 发行目录将头文件、导入库、动态库和示例分开存放。部署应用时应把与编译时相同版本的 DLL 和第三方依赖作为一个受控版本整体发布。

运行时目录
----------

通常需要准备：

* 应用程序或 demo 可执行文件；
* ``bin`` 中对应模块 DLL；
* ``PLC_SDK.dll`` 使用的 ``snap7.dll``；
* CameraSDK/AGV 等模块自身依赖的厂商或协议 DLL（以现场发布包为准）；
* 与任务匹配的 JSON/TXT 配置和日志目录。

推荐通过应用启动器配置 DLL 搜索路径，而不是把不同 SDK 版本的 DLL 混放在系统目录。Windows 下可以把 SDK ``bin`` 加入进程环境的 ``PATH``，Python 3.8 及以上也可以使用 ``os.add_dll_directory``。

配置文件
--------

配置文件路径应由应用传入绝对路径或由明确的工作目录规则解析。仓库 demo 使用 ``./data/...`` 相对路径，但这些数据位于 ``scripts/JsonSDK/data``，并不自动出现在 CMake demo 的工作目录中。

跨语言集成规范
--------------

应用层使用 Python ``ctypes`` 整合底层 SDK 时，必须遵循以下约定：

* ``ctypes.Structure`` 的字段类型、顺序和内存对齐必须与 C++ 结构体一致；采用 ``#pragma pack(1)`` 的结构体，Python 侧也必须设置 ``_pack_ = 1``。
* 遵循“谁创建、谁释放”原则。调用 ``AGV_Create``、``Robot_Create`` 或 ``plc_create`` 后，在正常退出和异常路径都显式调用对应的 Destroy 函数。
* 传入 C ABI 的字符串先用 ``.encode('utf-8')`` 转换为字节流指针，并确保指针在调用期间有效。

系统联调与异常处理
------------------

联调时应建立模块间的联动防护机制：

* AGV、Robot、PLC 网络断线或 Inclinometer 串口中断时，触发项目定义的自动重连或安全停止流程，并通知机械臂暂停运动。
* 视觉和倾角仪计算出的位姿，在下发给机械臂前必须经过 ``KinematicsSolver`` 的奇异点检测和安全边界校验。
* 任何模块返回失败、超时或状态不一致，都应停止后续动作，记录上下文，并在人工确认后决定重试、回退或结束任务。

日志与诊断
----------

为每个任务设置独立日志目录，记录 SDK 版本、设备连接结果、状态变化、动作 ID、返回码和异常原因。日志中不要写入密码、密码哈希、客户数据或未脱敏的生产网络信息。

发布检查
--------

#. 在干净机器上验证 DLL 可以加载；
#. 验证所有依赖 DLL 位数与应用一致；
#. 验证配置文件字段、单位和版本；
#. 在无负载/低风险环境验证状态读取；
#. 完成急停、断线、超时和恢复测试；
#. 锁定 SDK commit、二进制校验和与设备固件版本。
